# P09 → P10 — Hand-off

This document records what landed in the **Phase 10 — Prototyping &
Interactivity (foundations)** slice and what was deferred. The full
phase spec (`docs/development_phases/phase-10-prototyping-and-interactivity.md`)
spans eight milestones (M1–M8). This slice shipped **M1 + M2 only**:
the substrate that all downstream phases (12, 13, 14, 15, 16, 17, 20, 21)
will consume.

---

## What landed

### Runtime — `packages/prototype-runtime/`

The runtime is the **in-process engine** used by editor previews and
the future viewer runtime; it must work without HTTP. Pure TS, no DB,
no I/O, no `eval`.

| Module                      | Purpose                                                                                                                                      | Tests |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ----- |
| `expression/compiler.ts`    | AST whitelist, rejects `eval`/`Function`/dynamic access. Thin adapter over `@domio/formula-engine`.                                          | ✓     |
| `expression/evaluator.ts`   | Pure AST walker. Reuses formula-engine's `evaluateSafe` + sandbox caps.                                                                      | ✓     |
| `expression/builtins.ts`    | `round`, `floor`, `ceil`, `abs`, `min`, `max`, `clamp`, `if`, `coalesce`, `length`, `match`, `formatNumber`, `formatCurrency`, `formatDate`. | ✓     |
| `var-store.ts`              | Typed var store + scope chain. `Object.is` change detection, snapshot/restore.                                                               | ✓     |
| `bindings-dag.ts`           | Topological propagation, cycle detection at registration.                                                                                    | ✓     |
| `rule-evaluator.ts`         | Priority + short-circuit evaluation of `ConditionalRule[]`.                                                                                  | ✓     |
| `action-executor.ts`        | 10 action kinds, single `dispatch(action, ctx)` entry.                                                                                       | ✓     |
| `branching/graph.ts`        | Adjacency list, Tarjan SCC, bounded DFS.                                                                                                     | ✓     |
| `branching/traverse.ts`     | `DEFAULT_MAX_HOPS = 100` cap.                                                                                                                | ✓     |
| `branching/cycle-detect.ts` | Returns reachable path on cycle.                                                                                                             | ✓     |
| `hotspot/hit-test.ts`       | Normalized geometry, LRU cache per slide, z-index aware.                                                                                     | ✓     |
| `overlay/stack.ts`          | Z-stack with `max_depth = 5`, focus-trap helpers.                                                                                            | ✓     |

**124 tests across the package, all green.** Reads compile-time-only —
runtime is tree-shakeable to a small footprint for the viewer.

### Service — `services/prototype-runtime/`

Hono CRUD following the canonical four-line tenant pattern (same as
`services/timeline-api`). Web-framework-free handlers live in
`services/prototype-runtime/src/handlers.ts`; an `app` builder assembles
them in `index.ts`. Web-framework-free handlers are testable with the
in-memory DAL only; Hono wires them in for production.

Endpoints (CRUD per entity):

- `GET /v1/tenants/:tenantId/decks/:deckId/hotspots`
- `POST /v1/tenants/:tenantId/decks/:deckId/hotspots`
- `GET /v1/tenants/:tenantId/decks/:deckId/hotspots/:hotspotId`
- `PATCH /v1/tenants/:tenantId/decks/:deckId/hotspots/:hotspotId`
- `DELETE /v1/tenants/:tenantId/decks/:deckId/hotspots/:hotspotId`
- … same shape for overlays, branching-edges, interaction-states,
  variables, variable-bindings, conditional-rules.

Optimistic-lock 409 returns the body's `currentVersion` for the client
to rebase against. **39 service tests, all green.**

### Canvas ops — `packages/canvas/src/history/ops.ts`

Six new op types, each producing forward + inverse and registered in
`applyOp`:

| Op                  | Storage                             | Forward kind             |
| ------------------- | ----------------------------------- | ------------------------ |
| `HotspotOp`         | `slide['x-domio:hotspots']`         | add / patch / remove     |
| `OverlayOp`         | `slide['x-domio:overlays']`         | add / patch / remove     |
| `BranchingEdgeOp`   | `slide['x-domio:branching-edges']`  | add / remove             |
| `VariableOp`        | `slide['x-domio:variables']`        | write / clear            |
| `ConditionalRuleOp` | `props['x-domio:conditional-rule']` | create / update / delete |
| `VariableBindingOp` | `props['x-domio:variable-binding']` | create / update / delete |

All commits flow through the HistoryEngine (undo/redo safe). **63 tests
in `ops.test.ts` (25 new + 38 existing).**

### Editor — `apps/editor/src/panels/`

Two new left-side tabs:

- **Connections** (`p10-connections-tab`)
  - Hotspots sub-tab — add/remove hotspots wired to a slide.
  - Branching sub-tab — add/remove branching edges with optional
    `ruleId`.
  - Overlays sub-tab — CRUD overlays (modal/tooltip/drawer/popover/
    sheet; size strategy; persistent flag).
  - Graph sub-tab — runs `BranchingGraph.validate()` and shows
    `Has cycle: yes/no`, unreachable count, islands, multi-start.
- **Variables** (`p10-variables-tab`)
  - Variables sub-tab — CRUD variables (scope + type pickers; numeric
    defaults parsed with `Number(value) || 0`).
  - Rules sub-tab — CRUD conditional rules (priority, action picker),
    inline "Test rule" preview compiles and evaluates the expression
    against the current VarStore snapshot. Compile errors surface
    inline.

**22 component tests** (11 connections + 11 variables) **+ 9 Playwright
e2e**, all green.

### Contracts

- `contracts/schema/v1/` — 7 new JSON Schemas (draft 2020-12,
  `additionalProperties: false`, `$id` matching the repo convention):
  `hotspot-v1`, `overlay-v1`, `branching-edge-v1`, `interaction-state-v1`,
  `variable-v1`, `variable-binding-v1`, `conditional-rule-v1`.
- `contracts/openapi/v1/` — 4 new OpenAPI 3.1.0 yamls:
  `prototype-hotspots`, `prototype-overlays`, `prototype-variables`,
  `prototype-rules`. Bearer auth, `tenant_id` required query,
  `operationId` per endpoint.

### Migrations

- `0025_phase10_prototyping.{up,down}.sql` — 7 tables: `hotspots`,
  `overlays`, `interaction_states`, `branching_edges`, `variables`,
  `variable_bindings`, `conditional_rules`. Each carries `tenant_id`
  with an RLS policy that reads `current_setting('app.tenant_id', true)`
  or honors `current_setting('app.bypass_rls', true) = 'on'`. **All
  policies build via `EXECUTE format(...)` so the policy-name is a
  separate argument** (lesson learned: `'%I_tenant_isolation'` is a
  single identifier and breaks on most Postgres builds).
- `0026_phase10_prototyping_indexes_seed.{up,down}.sql` —
  `gin(geometry)` on `hotspots`, `gin(state_machine)` on
  `interaction_states`, `(deck_id, slide_id, priority DESC)` on
  `conditional_rules`. Seeds 4 default hotspots + 2 default overlays
  for the `system` tenant.
- `0027_phase10_state_machines.{up,down}.sql` (M3) — additive over
  `interaction_state`: `persist_instance_state boolean NOT NULL DEFAULT false`,
  `interaction_state_instance_idx` on `(tenant_id, deck_id, instance_id)`,
  and a partial index `interaction_state_persist_idx` for the
  `persist_instance_state = true` slice.

Migration harness extended with a P10 block: **7/7 green** (apply,
columns, indexes, RLS policies, seed counts, full insert chain,
rollback).

## What did not land (deferred)

These items belong to later milestones or are intentionally deferred.
Each is captured here so the next phase can pick them up without
re-discovery work.

### M3 — Component state machines (shipped)

- Runtime (`packages/prototype-runtime/src/state-machines/`):
  `StateMachine`, `TransitionEvaluator`, `EventBus`, `StateScope`.
  The precedence ladder is
  `focus > press > click > hover > default`. `StateScope` supports
  `session | slide | deck | persistent_session` and exposes a
  per-instance `persistInstanceState` flag that the editor
  toggles in the panel.
- Service (`services/prototype-runtime/src/`): `createInteractionState`
  accepts the full `{ states, transitions, initial }` JSONB; new
  `getInteractionState`, `patchInteractionState`,
  `deleteInteractionState` and `transitionInteractionState`
  handlers, plus `findByInstance(instanceId)` on the DAL. Six new
  handlers wired through `handlers.export`.
- Contracts:
  `contracts/schema/v1/state-machine-v1.schema.json` (JSON Schema
  draft 2020-12, `additionalProperties: false`, `states` is an
  object map of `{label?, meta?}` nodes) and
  `contracts/openapi/v1/prototype-state-machines.yaml` (list / get /
  create / patch / delete + `POST .../transition`).
- Editor panel (`apps/editor/src/panels/state-inspector-panel.tsx`,
  BEM classnames, `m3-` testid prefix): add-machine form, per-row
  remove, advance with event selection, pause-and-inspect toggle,
  `persist` checkbox, transition graph rendered in the runtime's
  precedence order. Mounted in `EditorRoot` as the
  `state-inspector` left-side tab.
- Postgres: `0027_phase10_state_machines.{up,down}.sql` adds
  `interaction_state.persist_instance_state` plus an instance
  lookup index and a partial index for the persistence flag.
- E2E: `apps/editor/e2e/p10-m3-state-machines.spec.ts` — 6 smoke
  tests covering open / add / transition graph / pause /
  remove / persist.

Not yet: full visual transition-matrix editor, guard compilation,
animated preview. These land in P11.

### M4 — Forms, calculators, device frames (landed in M4-r1)

- **Forms runtime** (`packages/prototype-runtime/src/forms/`):
  - `FormRegistry`, `input-validator.ts` (coercion, async debounced
    `runValidator`, `DEFAULT_ASYNC_DEBOUNCE_MS`),
    `autosave-policy.ts` (`AutosavePolicy`,
    `DEFAULT_AUTOSAVE_DEBOUNCE_MS`). 34 tests in
    `form-registry.test.ts`.
- **Calculator runtime**
  (`packages/prototype-runtime/src/calculators/`):
  - `CalculatorDef` (form + graph modes), `validateCalculatorDef`,
    `recomputeEngine` — topological propagation, cycle detection,
    sandboxed builtins (`sum`, `average`, `min`, `max`, `if`,
    `coalesce`, `clamp`, `round`, `formatCurrency`, `irr`, `npv`),
    array-literal support, 38-digit precision via
    `@domio/decimal128`. 29 tests.
  - Newton-Raphson IRR + bisection fallback. Negative-IRR paths covered.
  - `round($x, 1)` uses `half-down` so `round(1.55, 1) === 1.5`.
- **Device-frame runtime**
  (`packages/prototype-runtime/src/device-frames/`):
  `DeviceFrameRegistry`, `DEFAULT_DEVICE_FRAMES` (iPhone 15 / Pro Max,
  iPad 11", Desktop 1280 / 1920), `findDefaultFrame`. 8 tests.
- Migration harness: P10-M3 block (apply / columns / indexes / RLS /
  round-trip / scope check / rollback) — all green.
- MCP server tools for M4 entities land in M8.

### M6 — Quizzes + auto-advance (landed)

- **`@domio/prototype-runtime` quiz + sequence engines**
  - `quizzes/quiz-runtime.ts` — `QuizRuntime` with deterministic
    Mulberry32-seeded question order; supports all nine question
    types: `multiple_choice`, `multi_select`, `true_false`,
    `short_answer` (Levenshtein typo tolerance, default 0.85),
    `fill_blank`, `drag_to_match` (keyboard-only a11y), `hotspot_quiz`
    (point-in-polygon + centroid distance with partial credit),
    `flash_card`, and `short_answer_llm` (async grader with a
    confidence fallback queue below `DEFAULT_LLM_FALLBACK_THRESHOLD
= 0.7`).
  - `quizzes/xapi-emitter.ts` — produces xAPI 1.0.3 statements
    (`experienced`, `answered`, `completed` + `passed/failed`)
    replayable by Yet Analytics SCORM Cloud.
  - `sequences/timeline-runtime.ts` — `TimelineRuntime` with
    `pause()/resume()` accumulating `pausedTotalMs`, three
    interruption policies (`ignore | queue | abort`), visibility-aware
    tab-backgrounded clock handling, reduced-motion default-off,
    and `pauseWarnAtMs` default 30 min.
  - `sequences/visibility-listener.ts` — drives pause/resume off
    `document.visibilitychange`.
  - `sequences/interruption-policy.ts` — pure-function state machine
    `applyInterruption` / `dequeueInterruption`.
- **`@domio/prototype-runtime-service` quiz + sequence CRUD**
  - New repositories (`QuizRepository`, `QuizAttemptRepository`,
    `QuizAnswerRepository`, `QuizResultRepository`,
    `LlmReviewQueueRepository`, `PresentationSequenceRepository`)
    with full in-memory implementations.
  - New REST endpoints: `POST /v1/decks/:deck/quizzes`,
    `POST /v1/decks/:deck/quizzes/:quiz/attempts`,
    `POST /v1/quiz-attempts/:attempt/answers`,
    `POST /v1/quiz-attempts/:attempt/complete`,
    `GET /v1/quiz-attempts/:attempt`,
    `GET /v1/llm-review-queue`, `PATCH /v1/llm-review-queue/:id`,
    full CRUD on `presentation-sequences`.
- **Editor panels**
  - `apps/editor/src/panels/quiz-panel.tsx` — author + edit quiz
    with 9 question-type picker, prompt editing, threshold
    control, optimistic version bumping.
  - `apps/editor/src/panels/leaderboard-panel.tsx` — review the
    LLM-grade queue with approve/reject/override actions plus
    per-quiz aggregate stats.
  - `apps/editor/src/panels/sequence-inspector-panel.tsx` —
    configure timeline + per-slide ordering + interruption
    policy + pause-warn threshold.
- **Postgres migrations**
  - `0032_phase10_quizzes.{up,down}.sql` — `quiz`,
    `quiz_attempt`, `quiz_answer`, `quiz_result`,
    `llm_review_queue` tables + indexes + tenant-isolation RLS.
  - `0033_phase10_sequences.{up,down}.sql` — `presentation_sequence`
    - deck index + tenant-isolation RLS.
- **Contracts**
  - `contracts/schema/v1/quiz-v1.schema.json` — 9-type question
    schema.
  - `contracts/schema/v1/xapi-statement-v1.schema.json` — xAPI 1.0.3.
  - `contracts/schema/v1/presentation-sequence-v1.schema.json`.
  - `contracts/openapi/v1/prototype-quizzes.yaml` +
    `prototype-sequences.yaml`.
- **Tests** — 308 prototype-runtime package tests; 69 prototype-runtime-service
  tests; 25 panel tests (quiz + leaderboard + sequence); 9 e2e tests.

### M7 — Deep-link state codec (landed in M7-r1)

- New service `@domio/deep-link-service` (Hono) with
  `POST /v1/tenants/:tenant/decks/:deck/deep-links/shorten`,
