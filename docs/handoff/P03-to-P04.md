# Phase 03 → Phase 04 handoff

> **Status:** P03 closed; P04 landed.
> **Owners:** Editor lead (P03) → Realtime lead (P04).
> **Goal:** enumerate every extension point, interface, and message type P04
> depends on that originated in P03, plus the data-model changes P05 must
> make to `crdt_logs` and `presence_sessions`.

This document is the contract between the canvas editor (P03) and the
realtime gateway / CRDT substrate (P04). It is required by the P03 DoD
("Handoff doc to P04 lands in `/docs/handoff/P03-to-P04.md`") and feeds the
P04 §5 Stream B.3 ("CRDT ⇄ history engine bridge").

---

## 1. What P03 ships to P04

### 1.1 History engine as the local op source

P03's `packages/canvas/src/history/engine.ts` is the single producer of
local mutations. P04 reads from it through the bridge in
`apps/editor/src/sync/bridge.ts`.

Public surface P04 depends on:

| Symbol                    | Source                                    | Contract                                                                                                                                                                      |
| ------------------------- | ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `HistoryEngine.apply(op)` | `packages/canvas/src/history/engine.ts`   | Synchronously mutates the local scene graph and pushes a typed `HistoryOp` with `forward`/`inverse` onto the stack. P04 mirrors the op into Yjs via `SyncBridge`.             |
| `HistoryOp`               | `packages/canvas/src/history/ops.ts`      | `{ opId, opName, forward, inverse, authorId?, timestamp, branchId? }`. `opId` is a ULID; the same `opId` is the Yjs update's source-of-truth id and the `crdt_logs.op_id` PK. |
| `undo()` / `redo()`       | `packages/canvas/src/history/engine.ts`   | Pops the inverse off the stack and applies it. P04 must NOT collapse undo/redo into remote ops — undo only undoes local-authored entries.                                     |
| `RemoteOpApplied`         | `apps/editor/src/sync/bridge.ts`          | The synthetic history entry P04 emits when a remote op is applied. Carries `authorId` from the wire frame so the layers panel can attribute it.                               |
| `Snapshot`                | `packages/canvas/src/history/snapshot.ts` | Compaction boundary every 5,000 ops. P04's `SyncBridge` flushes a Yjs snapshot to the gateway at this boundary.                                                               |

### 1.2 `LocalPresenceAdapter` (P03 interface) → `RemotePresenceAdapter` (P04)

P03 ships the interface; P04 ships the implementation. The editor binds
to the interface, not to either adapter:

```ts
// packages/canvas/src/presence/local-presence.ts (P03)
export interface LocalPresenceAdapter {
  openLocalChat(at: WorldPoint): ChatHandle;
  emitPing(at: WorldPoint): void;
  subscribe(handler: (evt: LocalPresenceEvent) => void): () => void;
}
```

P04 implementation: `apps/editor/src/sync/presence.ts`
(`RemotePresenceProvider`). It speaks `Presence` / `PeerJoined` / `PeerLeft`
frames from `contracts/proto/domio/realtime/v1/realtime.proto` and
y-protocols/awareness for cursor broadcasts.

Swapping the adapter is a one-line change in `EditorRoot` and does not
touch any panel.

### 1.3 Per-element shape P04 must serialize into Yjs

The discriminated `Element` union in
`packages/schema/src/generated/scene-graph.ts` is the canonical shape.
P04's `bridge.ts` translates `HistoryOp`s into Yjs updates using these
mappings:

| Element field                          | Yjs storage                                          | Notes                                                                                                                              |
| -------------------------------------- | ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `transform.{x,y,w,h,rotation,scale}`   | `Y.Map` per slide doc                                | Properties of a layer node keyed by `element.id`.                                                                                  |
| `fills`, `strokes`, `effects`, `style` | `Y.Map` on the layer node                            | Renderer-facing structured forms (see `commands.ts`).                                                                              |
| `parentId`                             | `Y.Map` field; back-pointer index in `deck-root` doc | The RGA in the deck-root doc is the source of truth for slide order; per-slide docs own layer order via `Y.Array` indexed by ULID. |
| `text.content`                         | `Y.Text` on text layers                              | Bound to `TextLayer.text` so that two clients editing the same paragraph converge.                                                 |
| `autoLayout`, `constraints`            | `Y.Map` on the layer node                            | Layout worker reads from this directly.                                                                                            |
| `componentInstance.overrides`          | `Y.Map` on the layer node                            | Per-instance override map (P06 deepens).                                                                                           |
| `dataBindings`, `animations`           | `Y.Map` (opaque until P08 / P09)                     | Schema slot only; runtime lands in those phases.                                                                                   |
| `locked`, `hidden`, `z`                | `Y.Map` on the layer node                            | UI-only state; replicated for collaboration.                                                                                       |

Slides: `Y.Doc` per `slide:{slideId}`. Themes: `Y.Doc` per `theme:{themeId}`
(slots exist, P07 fills in). Deck root: `Y.Doc` for `deck:{deckId}` owns
slide RGA order and per-slide sub-doc GUID refs.

### 1.4 WebSocket message types P04 adopts (verbatim from `realtime.proto`)

```
contracts/proto/domio/realtime/v1/realtime.proto  (v1.0.0)

Frames:
  - Hello              (client → server)  JWT, deckId, branchId, resumeHLC?
  - Welcome            (server → client)  sessionId, currentHLC, serverVector
  - Op                 (client ↔ server)  opId, deckId, branchId, slideId?, authorId, hlc, parentHLC, payload (Yjs update bytes)
  - OpAck              (server → client)  opId, appliedHLC, duplicate?
  - Presence           (client ↔ server)  kind = cursor|selection|chat|ping|viewport
  - PeerJoined         (server → client)  peerId, userId, color, displayName
  - PeerLeft           (server → client)  peerId
  - BranchSwitch       (client → server)  newBranchId, baseCheckpointId?
  - BranchHead         (server → client)  branchId, hlc, opId
  - Error              (server → client)  code (UNAUTHENTICATED|DECK_NOT_FOUND|BRANCH_NOT_FOUND|REVISION_CONFLICT|RATE_LIMITED|PAYLOAD_TOO_LARGE|INTERNAL)

Enums:
  - OpType            (INSERT|UPDATE|DELETE|REORDER|REPARENT)
  - PresenceKind      (CURSOR|SELECTION|CHAT|PING|VIEWPORT)
  - RealtimeErrorCode (UNAUTHENTICATED|DECK_NOT_FOUND|BRANCH_NOT_FOUND|REVISION_CONFLICT|RATE_LIMITED|PAYLOAD_TOO_LARGE|INTERNAL)
```

The wire codec is a 4-byte big-endian length prefix followed by the
JSON-encoded protobuf payload. **No protobuf type tag** on the wire — the
`OpType` is carried inside the `Op` frame, not as a 1-byte discriminator.
This is enforced by `services/realtime-gateway/internal/transport/ws.go`
and matched by `apps/editor/src/sync/provider.ts`.

### 1.5 Files P04 added or extended (P03-side)

- `apps/editor/src/sync/` — new module:
  - `provider.ts` — typed event emitter over the WS transport
  - `backoff.ts` — jittered exponential reconnect
  - `local-queue.ts` — outbound op queue with persistence hook
  - `indexeddb-provider.ts` — y-indexeddb adapter for sub-docs
  - `bridge.ts` — History ⇄ Yjs bridge (local `forward` → Yjs update; Yjs
    update → synthetic `RemoteOpApplied` history entry)
  - `presence.ts` — `RemotePresenceProvider` (Yjs Awareness over the
    realtime presence channel)
  - `subdocs.ts` — re-exported from `@domio/yjs-shared`
- `apps/editor/src/canvas/` — new components:
  - `presence-overlay.tsx`, `cursor-chat.tsx`, `pointer-ping.tsx`
- `apps/editor/src/history/remote-op-applier.ts` — applies a remote op
  to the local scene graph without producing a per-op undo entry

### 1.6 Files P03 ships that P04 must NOT modify

- `packages/canvas/src/history/{engine,ops,snapshot,checkpoint}.ts` — P04
  wraps these, never edits them. If the history engine needs to change,
  P03 owns the change.
- `packages/schema/src/generated/scene-graph.ts` — schema is the source
  of truth. Schema changes go through P02.
- `packages/canvas/src/presence/local-presence.ts` — `LocalPresenceAdapter`
  is the contract; P04 adds a sibling `RemotePresenceAdapter`, not an edit.

## 2. What P05 must add

These are the data-model changes P05 owns (the spec says P05, but P04
already created the tables P05 needs to populate):

### 2.1 `crdt_logs`

| Column       | Type                                 | Notes                                                                                        |
| ------------ | ------------------------------------ | -------------------------------------------------------------------------------------------- |
| `op_id`      | `text PRIMARY KEY`                   | ULID; same value as `HistoryOp.opId` and the Yjs update's source-of-truth id.                |
| `deck_id`    | `uuid NOT NULL`                      | FK `decks(id) ON DELETE CASCADE`.                                                            |
| `branch_id`  | `text NOT NULL DEFAULT 'main'`       | Added by migration `0004_phase04_crdt.up.sql`. Phase 05 backfills historical rows to `main`. |
| `slide_id`   | `uuid NULL`                          | NULL for deck-level ops (reorder, branch switch).                                            |
| `author_id`  | `uuid NOT NULL`                      | User or agent id; for `author_kind = 'agent'` rows, the agent id is the author.              |
| `hlc`        | `bigint NOT NULL`                    | HLC ticks. Indexed for replay.                                                               |
| `parent_hlc` | `bigint NULL`                        | Causal parent.                                                                               |
| `payload`    | `jsonb NOT NULL`                     | Yjs update bytes, base64-encoded inside the JSON.                                            |
| `applied_at` | `timestamptz NOT NULL DEFAULT now()` | Server-side timestamp; distinct from HLC.                                                    |

Indexes (already in `0004_phase04_crdt.up.sql`):

- PK on `op_id`
- `(deck_id, branch_id, hlc)` for replay
- `(deck_id, branch_id, applied_at)` for the projection feed
- GIN `(payload jsonb_path_ops)` for op-type queries

RLS: a `deck_id IN (SELECT deck_id FROM user_deck_acl WHERE user_id = app.current_user_id())` predicate. The `app.bypass_rls` escape hatch is honored.

### 2.2 `presence_sessions`

| Column          | Type                                                   | Notes                                                                         |
| --------------- | ------------------------------------------------------ | ----------------------------------------------------------------------------- |
| `session_id`    | `uuid PRIMARY KEY`                                     | Server-issued; survives reconnects within `EXPIRE 60`.                        |
| `deck_id`       | `uuid NOT NULL REFERENCES decks(id) ON DELETE CASCADE` |                                                                               |
| `user_id`       | `uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE` |                                                                               |
| `branch_id`     | `uuid NULL`                                            | Nullable; defaults to `main`.                                                 |
| `color`         | `text NOT NULL`                                        | `deterministicCursorColor(userId)` from `@domio/yjs-shared`.                  |
| `connection_id` | `text NOT NULL`                                        | The WS connection id; multiple rows per user across devices are allowed.      |
| `last_seen_at`  | `timestamptz NOT NULL DEFAULT now()`                   | Drives the `(deck_id, last_seen_at desc)` index for the "who's online" panel. |

Phase 16 extends this with `audience_*` columns (mirroring the audience
sub-doc set); Phase 15 adds `presenter_*` columns. P05 does not change
this table.

### 2.3 `branch_heads`

A shadow table P05 owns the full schema for, but P04 already writes to it
on every op apply:

| Column       | Type                                 | Notes                                     |
| ------------ | ------------------------------------ | ----------------------------------------- |
| `deck_id`    | `uuid NOT NULL`                      | FK `decks(id) ON DELETE CASCADE`.         |
| `branch_id`  | `text NOT NULL`                      | Default `'main'`.                         |
| `hlc`        | `bigint NOT NULL`                    | Highest HLC seen for this (deck, branch). |
| `updated_at` | `timestamptz NOT NULL DEFAULT now()` |                                           |

PK: `(deck_id, branch_id)`.

This is the table the realtime gateway reads to determine the live HLC
for outbound fan-out. P05 adds the merge-side reads (`SELECT … FOR
UPDATE`) on this table inside the branch-merge transaction.
