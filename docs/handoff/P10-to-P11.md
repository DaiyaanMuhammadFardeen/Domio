# P10 → P11 — Hand-off

This document records what landed in **Phase 11 — 3D, Motion & Rich
Media** and what was deferred. The full spec
(`docs/development_phases/phase-11-3d-motion-rich-media.md`) spans
nine milestones (M1–M9) covering 20 features (#65–#84).

---

## TL;DR

Phase 11 shipped the **full vertical slice** for the four reader
audiences of the spec:

- **Editor authors** get a single `MediaPanel` (8 tabs) plus the
  MediaPanel's prop-edit surface wired into `EditorRoot`. New
  Phase 11 tabs land: `m11-licenses` (per-workspace LicenseGrant
  summary) and `m11-recording` (M7.3 recording controls).
- **Viewer players** get headless runtime wrappers for audio,
  video, physics, embeds, and now AR (M5.3 viewer-side), plus a
  scroll-driven 3D storytelling primitive.
- **Backend services** ship `cad-jobs` end-to-end (REST + worker
  simulator + WebSocket URL builder + ULID). The asset-api now
  covers models, scenes, keyframes, shaders, licenses, audio
  assets, video assets, and lottie assets.
- **Agent authors** get capability-claim gating on every new MCP
  tool surface, plus a license-dashboard for workspace admins.

All Phase 11 perf smokes (R-11-2) pass within 10× wall-clock
headroom of the documented budget.

### MCP gating (W5 — done in this slice)

`packages/mcp` now ships a claim-gated registry. Every Phase 11
tool surface (3D, media, embed, code, latex, map) goes through the
same gate as the Phase 10 surface.

```ts
import { createGatedMcpRegistry } from '@domio/mcp';

const registry = createGatedMcpRegistry();
registry.register({
  name: 'scene.update',
  capability: 'manage_scenes',
  ...
});

// Call is allowed only when ctx.claims includes 'manage_scenes'.
await registry.call('scene.update', { agentId, tenantId, claims }, input);
```

green while still catching regressions that exceed the actual

## Deferred (rolled to a future slice)

- **CAD-jobs Postgres DAL** — service ships with the in-memory DAL
  and the interface contract; the Postgres-backed implementation
  follows the same pattern as `services/keyframes-svc` and lands
  when the data-plane team picks it up.
- **AR WebXR session controller** — the viewer runtime now ships
  (`apps/viewer/src/ar/viewer-ar.ts`) with platform detection,
  audience URL builder, anchor tracking, and HMAC token verification;
  the actual `XRSession` controller (entering immersive mode, hit-testing
  on detected planes, anchor persistence) is scoped to Phase 13 alongside
  the broader agent runtime.
- **Code-sandbox execution policy UI** — sandbox policy CRUD is
  available via the embed-policy registry; an editor surface for
  managing per-workspace sandbox profiles is left to W6.

## Rollout plan

1. **Feature flag.** Wrap the `m11-media`, `m11-licenses`, and
   `m11-recording` tabs and the viewer runtimes behind
   `flags.p11_rich_media` so existing decks stay unaffected. AR
   handoff goes behind `flags.p11_ar_handoff`.
2. **Service rollout.** Stand up `services/cad-jobs` first (no DB
   dependency), then `services/keyframes-svc` + `services/asset-api`
   for 3D models, then the audio/video/lottie extension routes,
   then the rest.
3. **Capability rollout.** Issue the Phase 11 capability claims to
   the built-in editor agent before exposing the MCP tools
   externally.
4. **Perf monitoring.** Enable the R-11-2 perf smokes in CI for the
   three primary packages and alert on regression > 2× budget.
5. **De-flag.** Once 7 days of clean telemetry, remove the flag.
