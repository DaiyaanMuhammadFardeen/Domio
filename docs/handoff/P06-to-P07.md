# Phase 06 → Phase 07 handoff

> **Status:** P06 components/templates closed; P07 theming, brand & design tokens landed.
> **Owners:** Component/template lead (P06) → Stream A (theme-service + brand-service + workers).
> **Goal:** document the surfaces P07 consumes from the component ecosystem and the surfaces P08–P22 can build on.

## 1. P06 inputs consumed by P07

- The component catalog (`@domio/components`) exposes stable `catalogId`/`version` pairs that P07's brand-kit attribution and per-deck override propagation use to lock against off-brand modifications.
- The template surface (`@domio/templates`) emits a `template.kit_id` claim that P07's brand governance pipeline carries forward into brand-kit audit rows.
- Marketplace listing schema (`marketplace_listing`, `license_grant`, `revenue_share_event`) is the wire format reused by P07's theme marketplace (#45).
- Smart component props resolve through token references; P07's theme apply surfaces (`theme.applied`, `theme.overrides_set`) update those resolutions without touching the component layer.

## 2. P07 delivered surfaces

### 2.1 Design tokens + theme engine

- `packages/tokens` — canonical typed token schema (`color`, `typography`, `spacing`, `radius`, `shadow`, `motion`, `content`, `border`). Pure-function sRGB ↔ OKLCH conversions, WCAG 2 contrast, APCA Lc, ΔE_OKLab, and gamutmapping (`clampToGamut`).
- `packages/theme` — token resolution (`resolve.ts`), batch resolution (`batch.ts`), alias-cycle detection, referrer finder, theme-diff computation, and inheritance chain inspection.
- `services/theme` — REST + DAL for design tokens, themes, theme versions, per-slide overrides, theme-application events. `publishedAt`-pinned immutability for theme versions.

### 2.2 Brand kits + multi-brand contexts

- `services/brand` — brand kit CRUD (logos, palettes, type system, imagery rules), sub-brand DAG with cycle detection, brand contexts, extraction-job record, attestation gate before publish.
- `workers/brand-extract` — deterministic URL → brand-kit extractor with attribution block, color/font/logo helpers, palette token-ID suggestion (`color.brand.*`).
- Brand kit content hashing (SHA-256 over canonicalized JSON) and immutable published form are enforced at the DAL.

### 2.3 Custom fonts

- `services/font` — `.woff2/.woff/.otf/.ttf/.ttc` upload (≤ 25 MB / file, ≤ 50 fonts / kit default), license-status inference (`permissive | restricted | unknown`), glyph-coverage report per Unicode block, SHA-256 duplicate detection, anti-piracy heuristic gating (score ≥ 0.8 throws `FontLicenseBlockedError`), restricted + expired license rejection.

### 2.4 Lint and accessibility

- `services/lint` — two-pass style lint engine; rules: off-brand color (BLOCK), off-brand font (WARN), off-token spacing (INFO), low contrast (BLOCK via WCAG), alias loops (BLOCK). Findings carry structured `fixProposal` payloads (replacementToken, deltaE, old/new values) for one-click apply.
- `workers/accessibility-audit` — WCAG (AA 4.5:1 / AA-Large 3:1 / AAA 7:1) + APCA (Lc ≥ 60) + Brettel/Vienot/Mollon dichromacy matrices + ≥30° OKLCH palette suggestion; decorative tokens never block; audit reports BLOCK / WARN / INFO severities.

### 2.5 Dark / light pair generation

- `workers/theme-pair` — `generateDarkTheme` / `generateLightTheme` walk source themes and remap color tokens in OKLCH with lightness flip, chroma compensation (Helmholtz-Kohlrausch), hue preservation ±10°, gamutmapping, and grey fallback for low-chroma colors. Token categories present in source remain present in output.

### 2.6 Marketplace preview + install

- `services/marketplace-preview` — listing CRUD with `draft | published | archived` lifecycle; canonical SHA-256 content-hash verification on install; license-bundle enforcement (restricted assets require admin override); a11y certification gate (`a11yCertified` is required for `featured`); opt-in buyer sample reviews; install always materializes a brand-kit draft and never auto-applies to existing decks.

### 2.7 Editor surfaces

- `apps/editor/src/panels/theme-brand-panel.tsx` — left-side panel providing theme picker, brand-kit picker, dark/light scheme toggle, per-slide palette override, and a11y audit affordance. Persists through the autosave facade (`theme.applied`, `theme.override_set`, `theme.color_scheme_changed`, `brand.context_changed`).
- `apps/editor/src/lib/theme-audit.ts` — shared a11y audit types (`A11yAuditFinding`, `A11yAuditReport`) consumed by the panel and the future MCP `token.audit_a11y` tool.

### 2.8 MCP brand-aware tool surface

- `services/mcp-server/src/brand-tools.ts` — implements `apply_theme`, `token.audit_a11y`, `theme.suggest_palette` with brand-context scope enforcement (`BRAND_SCOPE_VIOLATION` when an agent scoped to Brand A touches Brand B). Dependencies are injected as `BrandToolDeps` so the live transport wires this against the real services in Phase 13.

## 3. Contracts P08–P22 may depend on

1. Token resolution through `theme_service.resolve()` is the single entry point for canvas / chart / animation / shader values.
2. Brand-kit published form is immutable; mutations go through `unpublish` → edit → `publish`. Audit row written on every transition.
3. Marketplace installs always produce a `brand-kit draft`; they never auto-apply to existing decks (per §4.8 DoD).
4. Lint findings carry structured `fixProposal` payloads — chart palette identifiability checks under CVD (P08 §10.3) consume the same shape.
5. A11y audit (`token.audit_a11y`) returns severity, location, and suggested fix; the AI accessibility assistant (#122, P12) reuses the same shape.
6. MCP tools enforce brand-context scope; P13 agent edits (#221–236) inherit the same `BRAND_SCOPE_VIOLATION` rule.
7. Sub-brand relationships are a DAG; cycle attempts raise `SubBrandCycleError` at the DAL boundary and `403 SUB_BRAND_CYCLE` at the HTTP boundary.
8. Theme application emits a single `theme.applied` event with `tokensChangedCount` and `latencyMs`; the analytics surface (P17) consumes this for off-brand violation reporting.

## 4. Observability and audit contract

Metrics:

- `theme_apply_total` / `theme_apply_duration_ms` (p95 < 300 ms target on 200-slide decks).
- `brand_kit_create_total` / `brand_kit_publish_total` / `brand_kit_archive_total`.
- `brand_extraction_started_total` / `brand_extraction_latency_ms`.
- `font_upload_total` / `font_license_blocked_total`.
- `lint_findings_total{severity}`.
- `a11y_findings_total{severity}`.
- `marketplace_install_total` / `marketplace_install_rejected_total`.

All services (`theme-service`, `brand-service`, `font-service`, `lint-service`, `marketplace-preview-service`) write append-only audit events into their `audit_brand_event`-shaped rows. The `marketplace_preview` and `brand` services share the same audit-row shape so the P20 governance dashboard can aggregate across surfaces.
