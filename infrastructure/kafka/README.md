# Phase 17 — Kafka (analytics ingest plane)

Apache Kafka in KRaft mode for the Phase 17 analytics ingest pipeline.

## Why Kafka (vs. NATS JetStream)?

NATS JetStream is the existing in-process bus for the realtime gateway,
participant gateway, and intra-cluster service-to-service messaging. We are
**not** replacing it.

Kafka is added for the analytics ingest pipeline specifically because:

1. **Replay semantics.** Kafka retains events for 7 days (configurable) and
   supports rewinding consumers to any offset, which the columnar loader and
   session-archiver worker depend on. NATS is fire-and-forget by default.
2. **Partition-key determinism at scale.** A single partition is consumed by
   exactly one consumer instance, which is how we guarantee sessionization
   ordering for W4. NATS has similar guarantees via JetStream subjects but
   its operational tooling for the 200k events/sec ingest SLO is less mature.
3. **Long-term cold storage.** Kafka's `log.segment.bytes` + object-store
   tiering is the foundation for the 7-year cold Parquet retention target.
4. **Ecosystem.** KafkaJS (Node) and `confluent-kafka-go` (Go) are the
   standards in this space; we already pull kafka-native client patterns
   from production-grade services.

## Layout

- `docker-compose.kafka.yml` — KRaft single-broker dev compose, extends the
  root `infrastructure/local/docker-compose.yml`.
- `kraft/server.properties` — broker config (single-node, no ZooKeeper).
- `broker.env` — environment defaults for `services/event-ingest` and the
  various Kafka consumers (columnar-loader, sessionization, crm-sync, etc.).
- `topics/` — runtime mount point for the init sidecar's readiness signal.

## Topic ownership

| Topic                                           | Producer                          | Consumer                                                           |
| ----------------------------------------------- | --------------------------------- | ------------------------------------------------------------------ |
| `events.ingest.raw`                             | `services/event-ingest`           | columnar-loader, sessionization, crm-sync, notification-dispatcher |
| `events.ingest.normalized`                      | columnar-loader (post-sessionize) | analytics-warehouse, ab-measurement                                |
| `session.events`                                | sessionization                    | analytics-warehouse                                                |
| `crm.sync.queued`                               | crm-sync (adapter-level)          | crm-sync worker                                                    |
| `crm.sync.sent` / `crm.sync.failed` / `crm.dlq` | crm-sync worker                   | analytics-warehouse (DLQ admin view)                               |
| `notification.triggered` / `.sent` / `.failed`  | notification-dispatcher           | analytics-warehouse                                                |
| `experiment.concluded`                          | ab-statistics                     | analytics-warehouse                                                |
| `heatmap.refreshed`                             | heatmap-generator                 | analytics-warehouse                                                |
| `live_session_summary.generated`                | live-analytics                    | analytics-warehouse                                                |
| `team_analytics.refreshed`                      | team-analytics                    | analytics-warehouse                                                |
| `consent.events`                                | viewer-identity                   | event-ingest (consent gate)                                        |

## Partition keys

All topics with a `viewer_id_key` MUST partition on that key so that
sessionization (W4) remains deterministic. The `partition_key` is documented
in each event JSON Schema at `contracts/events/ingest/*.json`.

## Local dev

```bash
docker compose -f infrastructure/local/docker-compose.yml \
               -f infrastructure/kafka/docker-compose.kafka.yml \
               up -d
docker logs domio-kafka  # wait for "KafkaServer id=1 started"
```

## Production

Production brokers ship a 3-node KRaft cluster with TLS + SASL_SCRAM
generated by `/infrastructure/terraform/modules/kafka/`. The `broker.env`
file is the contract that application services code against — never bake
broker hostnames into code.
